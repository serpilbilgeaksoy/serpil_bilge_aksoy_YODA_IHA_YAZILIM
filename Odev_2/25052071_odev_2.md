# Git ve GitHub Temel Kavramlar

## 1. GitHub Nedir ve Git ile İlişkisi Nasıldır?

GitHub projemize ait tüm dosyaların ve değişikliklerin bulunduğu alan olan uzak repository hizmeti veren web tabanlı bir araçtır. GitHub Git üzerine kurulmuştur. Git ve GitHub arasındaki ilişkiyi belirtmek gerekirse; Git teknolojinin kendisi, GitHub ise bunun web tabanlı bir platformu gibidir.

Uzak repository hizmeti sağlayan tek servis GitHub değildir; örneğin GitLab, Bitbucket, SourceForge, AWS CodeCommit gibi başka servisler de vardır, hatta kendimiz bile uzak repository servisi kodlayabiliriz ve oluşturabiliriz.

---

## 2. Neden GitHub Kullanırız?

- Diğer uzak repository servislerinde olduğu gibi, kendi bilgisayarımızın başına gelebilecek sorunlar, bilgisayarda çıkacak problemler ya da çalınma gibi beklenmeyen durumlarda uzak depo servisine sahip olmak isteriz.
- GitHub'ın kullanışlı bir arayüzü vardır ve kullanımı çok kolaydır.
- GitHub artık endüstri standardıdır; o nedenle Git ve GitHub birbirine çok karıştırılıyor ve endüstride genelde Git ile birlikte GitHub'ın da bilinmesi isteniyor.
- GitHub milyonlarca geliştiriciden oluşan bir developer community'sine sahiptir; örneğin açık kaynak bir proje oluşturduğunuz zaman bunu GitHub'da yayınladığınızda ilgi çekecek bir projeyse dünyanın çok farklı yerlerinden geliştiricilerle birlikte çalışabilirsiniz.
- Son olarak da statik web sayfalarınızı GitHub'da yayınlayabilirsiniz.

---

## 3. Git ve GitHub Temel Kavramları ve Uygulama Örnekleri

### 3.1. Repository (Depo), README.md, .gitignore ve License

- **Repository Oluşturma:** GitHub arayüzünden `+` tuşundan veya `New repository` butonundan yeni bir repository oluşturabiliriz. Repository'ye bir isim veririz, `Description` kısmına tanım yazabiliriz ve depoyu `Public` veya `Private` olarak oluşturabiliriz.
- **README.md Dosyası:** `README.md` dosyası genelde dışarıdan bizim repoya bakan kişilerin ilk gördüğü ve ilk okuduğu dosya olur yani projemiz hakkında tanım gibi bilgi veren bir dosyadır.
- **.gitignore Dosyası:** `.gitignore` dosyasında repoda olmasını istemediğimiz dosyaları ve klasörleri tutabiliriz. Farklı programlama dilleri ve teknolojiler için oluşturulan `.gitignore` şablonlarını bulabiliriz; mesela bir Python projesi oluşturduğumuzda Python şablonunu seçerek istemediğimiz klasörler ya da dosyalar `.gitignore`'a otomatik olarak eklenir.
- **License:** Birçok geliştirici kendi kodunu `Public` olarak GitHub'ın içerisine koyuyor olabilir ama bu kodu kafamıza göre istediğimiz şekilde kullanabileceğimiz düşüncesi yanlıştır; farklı lisans türleri ve seçenekleri vardır.

---

### 3.2. Yerel Depo Başlatma (`git init`), Stage (`git add`), Commit (`git commit`), Remote (`git remote`) ve Push (`git push`)

Boş bir repository oluşturduktan sonra kendi bilgisayarımızdaki projemizi uzak repository ile senkronize etmek için şu adımları ve komutları uygularız:

- Kendi bilgisayarımızda proje klasörümüzün içerisine girip `README.md` dosyasını oluştururuz ve Git repository'sini kendi bilgisayarımızda initialize etmek yani başlatmak için `git init` komutunu yazarız:
  ```bash
  echo "# starter" >> README.md
  git init
  ```
  `git init` dediğimizde yerel bilgisayarımızda yeni bir depomuz oluşturulur.
- `git status` yazdığımızda projede yeni eklenen veya değiştirilen (`modified`) dosyaları görürüz. Dosyaları staging area'ya eklemek için tek bir dosya adına göre veya tüm dosyaları aynı anda almak için `.` kullanarak `git add` komutunu çalıştırırız.
- Eklediğimiz dosyaları bir mesaj ile kayıt altına almak için `git commit -m` komutunu kullanırız. Eğer zaten takip edilen bir dosyada değişiklik yaptıysak hem `add` hem `commit` işlemini birlikte yapmak için `-am` parametresini de kullanabiliriz.
- Var olan kendi bilgisayarımızdaki Git repository'sine bağlanması gereken uzak repository adresini belirtmek için `git remote add origin` komutunu kullanırız; kayıtlı uzak depo adresini kontrol etmek için ise `git remote -v` yazarız:
  ```bash
  git remote add origin https://github.com/kullanici_adi/starter.git
  git remote -v
  ```
- `Push` itmek demektir; lokal bilgisayarımızdaki kodumuzu ve yaptığımız değişiklikleri remote bilgisayara, yani GitHub'daki depomuza göndermek için kullanılır. İlk gönderimde veya farklı branch belirtirken `git push -u origin master`, sonrasında tek bir branch üzerinden çalışıyorsak doğrudan `git push` yazarız.
- GitHub üzerinde `commits` kısmına tıkladığımız zaman yaptığımız değişiklikleri teker teker görebiliriz; yeni eklenen satırlar `+` şeklinde görünür ve ilgili commit satırlarına yorumlar bırakabiliriz.

### 3.3. Download ZIP ile Clone Arasındaki Fark

- **Download ZIP:** Herhangi bir GitHub reposunu `Download ZIP` yaptığınız zaman oradaki dosyaları olduğu gibi bilgisayarınıza kopyalarsınız ancak herhangi bir `.git` dosyası ve geçmişi kopyalanmaz.
- **Git Clone:** Uzaktaki var olan bir repository'yi olduğu gibi kendi bilgisayarımıza klonlamak istediğimizde HTTPS adresini kopyalayıp `git clone` komutunu kullanırız. Klasörün içerisine girdiğimiz zaman yalnızca proje dosyalarını değil, aynı zamanda `.git` klasörünü, yani var olan repository'yi olduğu gibi tüm Git özellikleriyle ve `origin` bağlantısıyla beraber almış oluruz. `Clone` ile `Download` arasında bu fark vardır.
  ```bash
  git clone https://github.com/kullanici_adi/genesis.git
  ```

---

### 3.4. Fetch, Merge ve Pull

GitHub'da bulunan uzak projemizde bir değişiklik yapıldığında ve aynı zamanda biz de kendi lokal bilgisayarımızda bir değişiklik yapıp `git push` dediğimizde Git hata verir. Çünkü uzakta bizim henüz almadığımız bir değişiklik vardır ve kendi değişikliğimizi göndermek için önce remote'ta olan değişikliği almamız gerekir; o nedenle bize `push` izni vermez.

- **`git fetch`:** Uzak bağlantıdaki değişikliği kontrol etmek ve indirmek için önce `git fetch` kullanırız. `git fetch` komutu uzak bağlantıdaki değişikliği bizim için kopyalar ama bunu doğrudan `merge` etmez; önce bir problem var mı diye kopyalar, ondan sonra bizim birleştirmemize izin verir.
- **`git merge`:** `git fetch` ile alınan değişiklikleri yerel çalışmamızla birleştirmek için `git merge` komutunu çalıştırırız.
- **`git pull`:** `git pull` çekmek demektir; yani GitHub'da bulunan değişiklikleri yerelimize çekmek için kullanılır. `git pull` aynı zamanda `git fetch + git merge` demektir: Önce `git pull` ile uzaktaki değişikliği yerel bilgisayarımıza alırız, ardından `git push` yaparak kendi yerel değişikliğimizi GitHub'a göndeririz. Yeni çekilecek bir değişiklik yoksa `git pull` bize `Already up to date`, göndereceğimiz yeni bir şey yoksa `git push` bize `Everything up-to-date` mesajını verir.
  ```bash
  git fetch
  git merge
  # veya ikisini tek seferde yapmak için:
  git pull
  ```

---

### 3.5. Merge Conflict Senaryosu

Hem remote'ta hem de lokal bilgisayarda aynı dosyanın aynı satırını değiştirdiğimiz zaman önce `git push` dediğimizde hata alırız, ardından `git pull` dediğimizde ise otomatik `merge` yapmaya çalışırken bir `conflict` ile karşılaştığını belirtir. `git status` dediğimizde `both modified` yani hem lokalde hem remote'ta değiştirildi uyarısını alırız.

İlgili dosyayı (örneğin `index.html`) metin editöründe açtığımızda şu yapıyı görürüz:
```html
<<<<<<< HEAD
<title>Local Genesis Project</title>
=======
<title>Remote Genesis Project</title>
>>>>>>> commit_id
```
Burada `HEAD` olarak belirttiği kısım kendi lokalde yaptığımız değişiklik, `=======` altındaki kısım ise GitHub'da yaptığımız değişikliktir. Hangisinin geçerli olmasını istiyorsak diğer kodu ve `<<<<<<< HEAD`, `=======`, `>>>>>>>` işaretlerini silip dosyayı kaydederiz. Sonrasında sırasıyla:
```bash
git add index.html
git commit -m "lokal baslik merge edildi"
git push
```
komutlarını çalıştırarak çakışmayı çözmüş ve değişikliğimizi uzaktaki repository'ye göndermiş oluruz.

---

### 3.6. Branch Kullanımı, Pull Request ve Merge İşlemi

Biraz önce gördüğümüz `merge conflict`lerden (merge karışıklıklarından ve çakışmalarından) kurtulmak ve ekip içinde `collaboration` yapmak için farklı `branch`ler kullanırız.

- **Yeni Branch Oluşturma ve Geçiş Yapma (`git checkout -b`):**
  Hem yeni bir branch oluşturmak hem de onun içerisine geçmek için şu komutu kullanırız:
  ```bash
  git checkout -b css-feature
  ```
  Böylece artık `master` üzerinde değil, oluşturduğumuz yeni branch içerisindeyizdir.
- **Branch Üzerinde Değişiklik ve Uzak Depoya Gönderme (`git push origin <branch_adi>`):**
  Değişikliğimizi kaydettikten sonra `add` ve `commit` işlemlerini yaparız. Remote'ta henüz bu branch olmadığı için gönderirken branch ismini de yazarız.
- **Pull Request ve Merge:**
  Değişiklikler GitHub'a gittiğinde GitHub arayüzünde `Compare & pull request` butonuna tıklayıp `Create pull request` deriz. Gerçek hayat projelerinde geliştirici olarak değişikliğimizi yapıp göndeririz; takım lideri de yapılan değişikliği inceleyip yorum yazabilir ve `Merge pull request` -> `Confirm merge` diyerek istenen değişikliği onaylayıp ana branch'e birleştirir. Birleştirme sonrasında ihtiyaç kalmadıysa `Delete branch` diyerek uzaktaki branch silinebilir.
- **Yerelde Ana Branch'e Dönme, Güncelleme ve Eski Branch'i Silme:**
  Lokal projemizde mevcut branch'leri görmek, ana branch'e dönüp uzaktaki birleştirilmiş değişiklikleri çekmek ve artık işe yaramayacak olan yerel branch'i silmek için şu komutları kullanırız:
  ```bash
  git branch
  git checkout master
  git pull
  git branch -d css-feature
  ```

### 3.7. Collaborator ve Contributor Kavramları

Herkes bir projeyle ilgili değişiklik yapıp doğrudan kendi kodunu gönderemez; bunun için projemize işbirliği yaptığımız diğer geliştiricileri, yani `collaborator`ları eklemek gerekir.
- **Collaborator Ekleme:** Repository'nin ana sayfasında `Settings` -> `Manage access` veya `Collaborators` kısmına gelip `Invite a collaborator` diyerek ilgili kişinin GitHub kullanıcı adını veya e-posta adresini yazıp davet göndeririz. Karşı taraf gelen daveti `View invitation` -> `Accept invitation` diyerek kabul ettiğinde projeye collaborator olarak atanır.
- **Contributor:** Projeye commit atarak katkı sunan geliştirici anlamındadır.

---

### 3.8. Açık Kaynak - Open Source, Watch, Star ve Fork Kavramları

- **Open Source Software:** Kaynak kodların kullanıcıların üzerinde çalışmak ve değişiklik yapmak üzere açılmasıdır. Ancak her açık kaynak kodlu projeyi istediğimiz gibi satabiliriz ya da dağıtabiliriz gibi bir durum yoktur; her projenin farklı lisanslama özellikleri olabilir.
- **Watch ve Star:** `Watch`, istediğiniz projeyi izleme (bir değişiklik oldu mu olmadı mı takip etme) anlamındadır. `Star` ise o projeye kısayol ve yıldız atabilmenizi sağlar.
- **Fork (Çatallama):** `Fork` çatal demektir; buradaki amaç projede collaborator olmayan birinin açık kaynaklı o projelere katkı sunması anlamına gelir. Eğer her geliştiriciyi doğrudan collaborator yapıp çalışırsak projede sık sık conflict'ler meydana gelir.
  - `Fork`taki mantık şudur: Bir projeyi `Fork` dediğimiz zaman o projeyi kendi GitHub hesabımızdaki repolarımıza kopyalar.
  - Kendi hesabımıza kopyalanan bu repoyu `git clone` ile bilgisayarımıza indirir, kendi alanımızda değişiklik yapıp `git add`, `git commit` ve `git push` ile kendi fork ettiğimiz repoya göndeririz.
  - Yaptığımız değişikliği orijinal repository'ye göndermek için kendi sayfamızdan `New pull request` -> `Create pull request` diyerek orijinal proje sahiplerinden merge talebi isteriz; bunu kendimiz merge edemeyiz, yalnızca orijinal projedeki yetkililer inceleyip merge edebilir.

---

### 3.9. GitHub Pages ile Statik Web Sayfası Yayınlama - Hosting

GitHub'da kişisel projelerimiz için yalnızca statik web sayfalarımızı ücretsiz olarak host edebiliriz:
1. Yeni bir repository oluştururken `Repository name` kısmına `<kullanici_adi>.github.io` yazarız ve `Public` olarak oluştururuz.
2. Bu repoyu `git clone` ile bilgisayarımıza klonlarız ve yayınlamak istediğimiz statik web sayfasının dosyalarını klasörün içerisine kopyalarız.
3. `git add .`, `git commit -m "web dosyalari yuklendi"` ve `git push` komutlarıyla dosyalarımızı GitHub'a göndeririz.
4. Dosyalar yüklendikten sonra `Settings` kısmında `GitHub Pages` bölümünde `Your site is published at https://<kullanici_adi>.github.io` bağlantısı üzerinden statik web sayfamızın ücretsiz olarak yayınlandığını görebiliriz.

## **Video 1: İHA Türleri ve Kullanım Alanları**

Bu videoda ilk olarak insansız hava aracının kullanım alanlarından, dünyadaki yaygın kullanımları ve yeni kullanım alanlarından bahsediliyor. Ardından insansız hava aracının türlerinden, nasıl çalıştığından ve bileşenlerinden bahsediliyor.

İlk olarak insansız hava araçlarının kullanım alanlarından bahsedersek çok farklı kullanım alanları var. Bunların bazıları savunma sanayi gibi alanlar ama onun haricinde günlük kullanımda da çok fazla yaygınlar:

1. **Teslimat - Drone Servisi:** Drone'lar herhangi bir işletmeden aldığı yemeği özellikle parklarda ve toplu alanlarda belli otomatlara getiriyor ve insanlar bu otomatlardan gelen yemeği teslim alabiliyorlar. Bu sayede çok hızlı ve güzel bir sistem elde etmiş oluyorlar.
2. **Dış Cephe Temizliği:** Özellikle gökdelen ve yüksek binalarda drone'lar dış cepheleri yıkayabiliyor. Bu da hem insan güvenliği hem de maliyet açısından çok fazla fayda sağlıyor.
3. **Haritalama - Drone Mapping:** Özellikle inşaat sektöründe ve tarihi projelerde kullanılıyor. Bazı spesifik alanların haritalarını drone'lara eklediğimiz sensörlerle elde edebiliyoruz ve burada milimetrik hata paylarıyla gerçekten o alanın üç boyutlu bir çıktısını elde etmiş oluyoruz.
4. **Arama ve Kurtarma:** Kurtarma çalışmalarında çok fazla kullanılıyor. Özellikle ulaşılması zor yerlerde arama ve kurtarma çalışmalarını yaparken operatörler çok fazla fayda sağlıyorlar.

İnsansız hava aracı türlerine geçersek aslında iki temel sınıf var:

- Birincisi **Multikopter** , yani birden fazla motorla çalışan sınıflar.
- İkincisi ise **Sabit Kanat** dediğimiz, daha çok kanatların kaldırma kuvvetiyle çalışan insansız hava araçları.

İlk bahsedeceğimiz sınıf **Multirotor**. Multirotor sınıfında motorların bulunduğu konuma ve motor sayısına göre bir isimlendirme oluyor:

- **Trikopter :** Bu model genelde Y şeklinde oluyor ve üç tane motor olduğu için bazı spesifik sistemlerde kullanılıyorlar.
- **Quadcopter, Hexacopter ve Octocopter:** Burada 4, 6 ve 8 motorlu sistemler var. Motor sayısı burada aslında itkiyi belirliyor; yani ne kadar ağır bir drone'un havaya kalkabileceğini belirliyor bizim için. Quadcopter genel görevlerde kullanılırken, Hexacopter ve Octocopter gibi 6 motorlu, 8 motorlu sistemlerde çok ağır yükler taşınabiliyor; mesela madencilerin jeneratörlerini taşıyan drone'lar veya zirai gübreleme ve ilaçlama yapan drone'lar. Multirotor'da motor sayısı seçimimiz daha çok görevimize ve yapmak istediklerimize bağlı olarak değişiyor. Ama motor sayısı arttıkça batarya kullanımımız daha fazla artıyor ve daha büyük bataryalar koymamız gerekiyor. Batarya ekledikçe drone'un ağırlığı artıyor ama motor ekledikçe de fazla itki elde ediyoruz; burada artı-eksi durumlarını değerlendirip doğru bir seçim yapmak gerekiyor.

**X8** ve **Y6** dediğimiz tasarımlarda birden fazla motoru aynı kanada koyuyorlar. Mesela X8'de dört tane kol var ama bu dört kolda sekiz tane motor var. Normalde döner kanatlarda **1'e 2 ağırlık-itki oranı** olur. X8 veya Y6 gibi tasarımlarda ise bu oran artıyor. Bu sayede çok daha hızlı manevra yapabiliyorlar ve çok daha hızlı yükselebiliyorlar. Örneğin DJI'ın tarım görevlerinde kullanılan 8 motora sahip X8 tasarımında drone'u var.

**QGroundControl Yazılımı:** Biz buna herhangi bir **FCU (Flight Control Unit)** bağladığımız zaman —ki uçuş kontrolcüleri drone'daki motorların hareketini ve dönüşünü belirleyen sistemlerdir— yazılımın içine girdiğimizde **Airframe** diye bir seçenek var. Burada kullanabileceğimiz drone tasarımlarını görüyoruz. Motorların yerleşimine göre bile farklı sistemler elde edilebiliyor: örneğin **X Quadcopter** tasarımında veya **+ Quadcopter** tasarımında farklı konfigürasyonlar görebiliyoruz. Bunu uçuş kontrolcümüzün ileri olarak varsaydığı yön belirliyor.

**Sabit Kanatlı (Fixed-Wing)** insansız hava araçlarına geçersek; bunların genel amacı daha çok kanatların kaldırma kuvvetiyle uçmak ve daha uzun mesafelerde uçabilmektir. Çünkü bir batarya 4-5 motora güç vermektense tek bir motora güç verdiğinde ve kanatlardan gelen fizik yasalarının avantajlarını kullandığında çok daha uzak mesafelere uçuş sağlayabiliyoruz. Sabit kanatlı İHA'larda arkada veya önde bir tane motoru olan modellerimiz var; bunun haricinde ön tarafta iki tane motoru olan sistemlerimiz de var. Sabit kanatlı İHA'lar çok uzun mesafeler uçabiliyorlar ama **pist ihtiyaçları** var; yani bir iniş veya kalkış yapmak istedikleri zaman bir piste muhtaçlar. 20 m/s hızla giden bir uçağı zeminin şartlarını ve İHA'nın durumunu hesaba katarak düzgün bir şekilde zemine indirmek kolay bir şey değildir.

**VTOL (Vertical Take-Off and Landing)** sistemleri var:

1. **Standart VTOL :** Hem sabit kanat hem de döner kanadın özelliklerini birleştiriyor ve 5 tane motoru tek uçakta bir araya getiriyorlar. Bu sayede iniş ve kalkışı istediğimiz yerde, istediğimiz zemine yapabilirken, İHA yükseldikten sonra sadece arka motoru çalışır ve sabit kanadın fizik avantajlarıyla bataryayı çok daha verimli kullanarak çok daha uzak görevlerimizi yapabiliriz.
2. **Tiltrotor VTOL:** Karbon borularla ekstra 4 motor koyup ağır bir sistem yapmaktansa, kanatların üzerinde iki tane ön tarafa, bir tane de arka tarafa motor konularak dönebilen motor yapısı elde ediliyor. Döner kanat gibi istediğimiz yerden dikey iniş kalkış yapıyoruz; kalktıktan sonra öndeki iki motor öne doğru katlanıyor. Böylece aynı motorları hem iniş-kalkış için hem de sabit kanatla ileri gitmek için kullanıyoruz. Çok daha verimli bir sistemdir ama standart VTOL kadar hassas bir iniş-kalkış sağlamayabilir.
3. **Tailsitter VTOL:** Sadece iki tane motoru olan bir VTOL türüdür. İki motor olmasından dolayı kontrol sistemi ve iniş-kalkışı biraz daha zordur.

Tekrardan QGroundControl yazılımına gelirsek; sabit kanat uçakların kontrol yüzeylerine göre ve VTOL tiplerine göre hazır **Airframe** konfigürasyonlarını üretimimize göre seçiyoruz. Bu yazılımda seçilen modeller ve frame'ler uzun çalışma ve hesaplamalarla hazırlanmış sistemler olduğu için, bunlardan tamamen farklı bir frame yapmak istersek bütün kontrol yazılımını baştan yapmamız gerekir ki bu çok karmaşıktır. O yüzden buradaki hazır frame'lere uygun sayıda motor ve kontrol yüzeyi seçmek çok daha mantıklıdır.

## **Video 2: DönerKanat ve SabitKanat İHA Nasıl Uçar?**

**İnsansız Hava Araçları Nasıl Çalışır?** Multirotor insansız hava araçları, her bir motorun oluşturduğu itki kuvvetlerinin toplamıyla birlikte kalkış, iniş ve yönelme yapıyor. Her bir motorun pilden gelen voltaj değerine ve kullanılan pervane inçine göre kendine ait bir itki değeri vardır. Eğer bütün motorlar aynı devirde ve aynı itki değeriyle çalışırsa ve toplam itki drone'umuzun ağırlığından yüksekse, herhangi bir yalpalama veya stabilizasyon kaybı olmadan dikey kalkış yaparız.

Motorların farklı devirlerde çalışmasına göre drone'umuzun alacağı yönelmeyi ve hareketi belirleyen üç temel eksen/parametre karşımıza çıkar: **Roll, Pitch ve Yaw**.

- **Yaw (Sapma):** Drone'umuzun dikey eksende kendi etrafında sağa ve sola dönmesini sağlar.
- **Roll (Yatış):** Drone'umuzun yanal eksende sağa ve sola hareket etmesini sağlar. Örneğin drone'un sola yatması için soldaki iki motorun daha az devirde, sağdaki iki motorun daha fazla devirde çalışması gerekir.
- **Pitch (Yunuslama):** Drone'umuzun öne veya arkaya doğru eğilmesini ve hareketini sağlar. Örneğin drone'un burnunu aşağı indirip öne yönelmesi için öndeki iki motorun daha az çalışması, arkadaki iki motorun daha fazla itki üretmesi gerekir.

**Motor Dönüş Yönleri ve Tork Dengesi:** Drone motorlarının yerleşimi ve pervanelerin takılış biçiminde önemli bir fizik kuralı devreye girer: Çapraz motorlardan bir çift **saat yönünün tersine** dönerken, diğer çapraz çift **saat yönünde** döner. Bunun sebebi, kollara uygulanan açısal torku merkezde sıfırlamaktır.

**Ağırlık Merkezi ve Uçuş Kontrolcüsü:** Normalde bütün multirotorlarda ağırlık merkezinin tam ortada olması gerekir. Uçuş kontrolcüsünün temel görevi uçağı havada stabil tutmak ve düşmemesini sağlamaktır. Eğer ağırlık merkezi ortada değilse dengenin bozulmaması için bir motorun 800 gram itki üretirken diğerinin 700-750 gram itki üretmesi gerekir. Uçuş kontrolcüsü sensörlerle durumu algılayıp bunu sürekli dengelemeye çalışır; ayrıca yazılımda ağırlık merkezinin motorlara olan konumunu parametre olarak girdiğimizde kontrolcü motorlara itkiyi doğrudan buna göre dağıtarak ağırlık merkezi kaçık olsa bile drone'un çok daha stabil uçmasını sağlar.

**Sabit Kanatlı İHA'ların Uçuş Prensibi:** Sabit kanatlı İHA'lar kanat profili sayesinde fizik yasalarını kullanır. Kanadın altından geçen hava düz giderken üstünden geçen hava kavisli bir yüzeyden geçer; aracın ileri doğru hızlanmasıyla beraber bu basınç/hız farkı kanatlarda yukarı yönlü bir **kaldırma kuvveti** oluşturur.

İçinde Windows/Linux gibi bir masaüstü işletim sistemi olmasa da gerçek zamanlı çalışan bir işlemcisi ve RAM'i vardır; tüm sensörlerden gelen verileri ve komutları işleyerek İHA'nın havada sağlıklı ve stabil bir şekilde tutunmasını sağlar.
6. **Ground Control Station (YKİ):** Yer istasyonundaki laptopumuza yüklediğimiz ve telemetri cihazı aracılığıyla İHA'ya bağlandığımız yazılımlardır. İHA üzerindeki parametreleri değiştirebilir ve görev tasarlayabiliriz.

**Avyonik Diyagram ve Fırçasız Motorlar:**
Pixhawk diyagramında GPS, telemetri, airspeed sensörü, kamera ve görüntü aktarım modülü, batarya, ESC'ler ve motorların bağlantıları yer alır.

- **Motor İsimlendirmesi :** Motorların büyüklüklerine göre itkisi ve hızı değişir. Örneğin `2212`, `2820` gibi dört haneli motor numaraları vardır; bu rakamlar motorun içindeki bakır bobinlerin sarıldığı **stator** kısmının **çapını** ve **yüksekliğini** ifade eder.
- **KV Değeri:** Örneğin motorun üzerinde `1250 KV` yazar. **KV değeri**, motorun **1 Volt başına yüksüz durumda dakikada kaç devir döneceğini** ifade eder; yani motorun dönüş hızını belirler. Yüksek KV her zaman iyi demek değildir; çünkü yüksek KV motorlarda çok hızlı dönüşten dolayı enerji daha fazla ısıya dönüşür ve verimlilik azalır.
- **Çalışma Prensibi:** Drone motorlarımızda içerideki bakır sarımlar elektrik akımıyla manyetik alan oluşturur; bu manyetik alan dış kısımdaki mıknatısları etkileyerek motorun dönmesini sağlar.

## **Video 4: İHA Temel Bileşenler-2**

**ESC, PDB ve Power Module:**

- **ESC - Elektronik Hız Kontrolcüsü:** Motorlarımız ESC'lere bağlanır. ESC'ler motorun hızını belirleyen sistemlerdir; motora bağlanan 3 kablosu vardır ve motor üzerindeki manyetik alanın frekansını/etkileşimini değiştirerek motorun dönüş hızını ayarlar.
- **PDB Güç Dağıtım Kartı:** Tek bir LiPo pilimiz veya paralel bağlı iki LiPo pilimiz olabilir; bu pili bütün ESC'lere seri bağlayamayacağımız için gücü güvenli ve doğru şekilde dağıtacağımız karta **PDB** denir.
- **Power Module:** Bir ucu PDB'ye, diğer ucu LiPo pile bağlanır; üzerindeki devre ve ince kablo sayesinde Pixhawk'a pilin anlık voltajı ve çekilen akım hakkında bilgi aktarır. Eğer VTOL gibi 100 Amper'in üzerinde yüksek akım çeken sistemlerle çalışıyorsak ve Power Module sınırını aşıyorsa, bu voltaj/akım verilerini doğrudan yüksek akım destekli PDB üzerinden de Pixhawk'a iletebiliriz.

**Batarya Hücre Sayısı ve Motor Verimlilik Tablosu:**

- **LiPo Piller (3S, 4S, 6S):** `3S` dediğimiz 11.1 Volt, `4S` dediğimiz 14.8 Volt, ayrıca `5S` ve `6S`'e kadar çıkan piller vardır.
- **Motor Datasheet Tablosu:** Seçilen voltaj ve pervane boyutuna göre motorun çekeceği maksimum akım, üreteceği itki, güç ve **verimlilik** değerleri yer alır. Akım arttıkça verimlilik düşer. Görevin gerektirdiği itki ve verimlilik hesaba katılarak güvenli sınırlar içinde motor seçimi yapılmalıdır.

**ESC Türleri ve Seçim Kriteri:**

- ESC'ler sinyal kablosuyla Pixhawk'a bağlanır ve içinde `BLHeli_32` veya `BlueJay` gibi gömülü yazılımlar çalışır.
- **BEC Çıkışlı ESC:** Bazı ESC'lerde sinyal ve toprak kablosunun yanında 3. bir güç kablosu bulunur; Pixhawk'un kendi gücü bağlanan sensörleri beslemeye yetmediğinde buradan ekstra güç verilebilir.
- **4-in-1 ESC:** FPV drone'larda veya küçük modellerde 4 ayrı ESC yerine tüm motorların tek bir küçük karta lehimlendiği 4'ü 1 arada ESC'ler kullanılır.
- **Opto ESC:** İçinde BEC regülatörü bulundurmayan, dışarıya 5V güç çıkışı vermeyen ESC türüdür.
- **ESC Amper Seçimi:** Motor maksimum 10 Amper çekiyorsa, ESC ve motorun yanmaması/zarar görmemesi için biraz güvenlik payı bırakılarak en az 15A veya 20A'lik bir ESC seçilmelidir.

**Flight Controller Donanımı, İşlemci Hızı ve Çoklu IMU:**

- Uçuş kontrol cihazı içinde **STM32** tabanlı mikrodenetleyiciler bulunur ve **EKF** gibi algoritmalarla stabilizasyon, navigasyon, motor yönetimi ve **Failsafe** protokollerini yürütür.
- **İşlemci Frekansı:** Örneğin 216 MHz veya 480 MHz hızları saniyedeki döngü sayısını ifade eder. Sensörlerden her saniye gelen verileri ne kadar hızlı işlersek, kontrolcü İHA'nın havadaki yalpalamasını o kadar hızlı hisseder ve o kadar hızlı tepki vererek uçağın daha stabil uçmasını sağlar.
- **Yedekli IMU Yapısı:** Gerçek hayatta titreşim ve ortam şartlarından dolayı sensör verilerinde her zaman bir gürültü olur. Üst seviye uçuş kontrolcülerinde **3 farklı IMU** bulunur; birincisinin verisi hatalıysa ikincisine ve üçüncüsüne bakılarak bu üç veri birleştirilir ve en doğru veriye ulaşılır.

**Sensörler:**

- **IMU (Inertial Measurement Unit):** İHA'nın ivmesini, dönüşünü ve yönelimini ölçer. İçerisinde iki temel sensör barındırır:
    1. **Akselerometre:** X, Y ve Z eksenlerindeki doğrusal ivmeleri ve yerçekimi vektörünü ölçer.
    2. **Jiroskop:** Aracın açısal hızını ölçer.
- **Barometre:** Hava basıncından yararlanarak yerden yüksekliğimizi tahminen bulur.
- **Lidar:** Hem 3B haritalama yapmamızda işe yarar hem de uçağın altına yerleştirildiğinde gönderdiği kızılötesi ışınlarla yerle aramızdaki gerçek mesafeyi doğrudan hassas olarak ölçer.
- **Manyetometre:** Aracın maruz kaldığı manyetik alan yoğunluğunu ölçer ve yön sapmalarını tespit etmemize olanak sağlar.

**PID Kontrol Algoritması (Proportional - Integral - Derivative):**

- Uçuş kontrolcüsünün içinde çalışan temel kontrol algoritmasıdır. Sensörlerden gelen hataya motorların ne kadar yoğunlukta ve nasıl bir tepki vereceğini belirler:
    - **P:** Anlık hataya tepki verir; sensörden gelen anlık veriye göre o anki düzeltme seçimini yapar.
    - **I:** Zamanla biriken kalıcı hatayı sıfırlamayı amaçlar.
    - **D:** Hatanın değişim hızını inceler ve tepkiyi sönümler.
- Her İHA'nın motor büyüklüğü, tasarımı, ağırlık merkezi farklı olduğu için kendine özgü optimum PID katsayıları vardır. Eğer PID değerleri yanlış olursa, örneğin sağa yatan bir drone kendini düzeltmek için sola aşırı tepki verir, salınım yapar ve havada stabil kalamayıp takla atarak düşer.

**GNSS / GPS ve RTK Teknolojisi:**

- **GPS / GNSS:** Dünya yörüngesindeki birden fazla uyduya bağlanarak uydulardan gelen sinyalin gecikme süresine göre dünya üzerindeki konumumuzu tespit eder. Navigasyon, havada sabit kalma ve eve dönüş algoritmalarında kullanılır.
- **RTK (Real-Time Kinematic) GPS:** GPS verilerini doğrulayan ikincil bir yer tabanlı sistemdir. Konumu bilinen sabit bir noktaya kurulan RTK baz istasyonu sayesinde İHA'nın GPS konum hata payı **1-2 santimetreye** kadar düşürülür.

**Sensör Füzyonu ve EKF (Extended Kalman Filter):**

- İHA'da GPS, barometre, manyetometre, IMU, airspeed gibi çok sayıda sensör vardır. **EKF**, doğrusal olmayan sistemlerin durumunu tahmin etmek için kullanılan bir matematik algoritmasıdır. Birden fazla sensörden gelen gürültülü verileri birleştirerek hata paylarını azaltır ve drone'un gerçek konumunu, hızını, Roll/Pitch/Yaw açılarını en doğru şekilde uçuş kontrolcüsüne bildirir.

**Telemetri Haberleşmesi:**

- İHA ile yer kontrol istasyonu arasındaki veri ve komut iletişimi sistemidir. İletişimin kopması İHA'nın kaybolması anlamına gelebileceği için menzil, çıkış gücü ve **şifreli haberleşme** çok önemlidir.

Görev bilgisayarı görüntüyü anlık olarak alıp üzerindeki yapay zeka birimleriyle işler, karar verir ve USB/seri kablo üzerinden Pixhawk'a anlık komutlar gönderir.

Ayrıca derinlik ölçen kameralar da bağlanabilir.

**Ground Control Station:**

- Operasyonel merkezimizdir. Kalkıştan görev noktalarına ve inişe kadar tüm uçuş önceden planlanabilir; canlı görüntü ve uçuş parametreleri takip edilebilir.
- **Acil Durum ve Log Analizi:** Uçak bir sorun yaşadığında neden Failsafe'e geçtiğini ve Pixhawk'un belleğine kaydettiği tüm uçuş günlüklerini incelememize olanak tanır.
- **Kablosuz Ağ ve SSH Bağlantısı:** Görev bilgisayarına takılan bir SIM kart modülü veya Wi-Fi görüntü/veri aktarım modülleriyle yer istasyonu ile İHA arasında kablosuz bir ağ oluşturulabilir; bu sayede hem gimbal kamera görüntüsü yere aktarılır hem de yerdeki bilgisayardan uçaktaki Jetson'a **SSH** ile uzaktan bağlanılabilir.
- Yer kontrol istasyonu yazılımları **açık kaynaklıdır**; bu sayede kaynak kodları üzerinde değişiklik yaparak kendi özel yer kontrol istasyonu arayüzümüzü geliştirebiliriz.

## **Video 6: İHA'nın Otopilot Yazılımları Nelerdir?**

**Otopilot Yazılımlarının Temel İşlevleri:**
İkinci bölüm olan programlama kısmında **ArduPilot** ve **PX4** gibi açık kaynaklı otopilot yazılımlarını inceliyoruz. Otopilot yazılımının 5 temel işlevi vardır:

1. **Sensör Füzyonu ve State Estimation :** Uçuş kontrol kartının içindeki ve dışarıdan bağlanan tüm sensör verilerini işleyerek drone'un pozisyonunu, yönünü ve hızını tahmin eder.
2. **Flight Control:** Yer istasyonundan veya görev bilgisayarından gönderilen üst seviye komutları motorlarda ve ESC'lerdeki fiziksel itki karşılığına dönüştürür.
3. **Mission Management :** Görev bilgisayarı kullanılmadığı durumlarda bile yer istasyonundan yüklenen uçuş planını baştan sona otonom olarak yönetir.
4. **Failsafe :** Batarya voltajının azalması veya EKF sensör verilerinde tutarsızlık oluşması gibi durumlarda İHA'yı korumak için güvenli moda alır.
5. **Flight Modes:** Kullanıcıya tam otonom rota takibinden kumanda destekli manuel uçuşlara kadar farklı kontrol modları sunar.

**ArduPilot ve PX4 Karşılaştırması:**

- **Tarihçe:** İkisi de birbirine yakın tarihlerde kurulmuş açık kaynaklı topluluklardır (ArduPilot 2009, PX4 2011).
- **Uçuş Modu Eşdeğerlikleri:** İsimleri farklı olsa da işlevleri birbirine çok benzerdir; örneğin PX4'teki `Offboard` modu ArduPilot'taki `Guided` moduna, PX4'teki `Mission` modu ArduPilot'taki `Auto` moduna eşdeğerdir.
- **Lisanslama Farkı :**
    - **ArduPilot (GPLv3):** Yazılımın içinde bir değişiklik yaptığımızda ve bunu ticarileştirdiğimizde, geliştirdiğimiz kodu açık kaynak olarak yayınlamak zorundayızdır.
    - **PX4 (BSD Lisansı):** Çok daha serbesttir; geliştirdiğimiz algoritmaları ve kodları gizli/kapalı tutabiliriz, sadece PX4 tabanlı olduğunu belirtmemiz ticari ürünler için yeterlidir.
- **Topluluk ve Güncellik:**
    - **ArduPilot:** Hobiciler ve DIY model uçak/drone topluluğu tarafından çok uzun süredir kullanıldığı için topluluğu daha geniştir ve forumlarda sorunlara cevap bulmak daha kolaydır; ancak güncellemeler ve yeni kütüphane entegrasyonları biraz daha yavaştır. Genelde **Mission Planner** ile kullanılır.
    - **PX4:** Daha güncel, kurumsal ve akademik/Ar-Ge projeleri ile kontrol mühendisleri tarafından aktif geliştirilen bir yapıya sahiptir. Genelde **QGroundControl** ile kullanılır .

**PX4 Uçuş Modları :**
Otopilot yazılımlarında bir sorun yaşadığımızda ilk bakmamız gereken yer resmi dokümantasyondur. Uçuş modları genel olarak **Manuel Yardımlı Modlar**, **Akrobatik Modlar** ve **Otonom Modlar** olarak üçe ayrılır:

1. **Position Mode :** **IMU, Barometre ve GPS** kullanır.
    - *Multikopterde:* Kumanda kollarını bıraktığımız anda İHA kendini 3 boyutlu konumda kilitler; rüzgar itse bile motorları çalıştırarak eski konumuna geri gelir.
    - *Sabit Kanatta:* Sabit kanat havada duramayacağı için, kumandayı bıraktığımızda GPS yardımıyla hem irtifasını hem de uçuş yönünü koruyarak düz ilerler.
2. **Altitude Mode :** **IMU ve Barometre** kullanır, GPS gerektirmez.
    - *Multikopterde:* Kolları bıraktığımızda aracı yatayda düzler ve yerden yüksekliğini sabit korur; ancak GPS kullanmadığı için rüzgar eserse yatayda sürüklenebilir.
    - *Sabit Kanatta:* Aracın yatışını ve irtifasını korur.
3. **Stabilized Mode :** Kumandaya daha çok yetki verilen moddur.
    - *Multikopterde:* Araç sadece yatay duruşunu korur; irtifa ve konum kontrolü tamamen pilottadır.
    - *Sabit Kanatta:* Roll ve Pitch açılarını kumanda eder, kollar bırakıldığında uçak kanatlarını düzeltir ancak hız ve irtifa kontrolü pilottadır.
4. **Mission Mode:** Kalkıştan inişe kadar önceden planlanan tüm görev noktalarının otonom takip edildiği moddur. Sabit kanatlı bir İHA Mission modunda piste iniş yaparken doğrudan inemez; önce bir **loiter** atıp kendini pistin iniş hattıyla hizalar ve ardından piste iner. Multikopter ise doğrudan hedef konuma gelip dikey alçalarak inebilir.

**Hold, Return, Land ve Offboard Modları:**

1. **Hold Mode - Otonom Bekleme / Güvenlik Modu:** GPS gerektirir. Multikopter olduğu yerde 3 boyutlu konumunu kilitleyerek havada bekler; sabit kanat ise havada duramayacağı için bulunduğu konum etrafında daire çizerek döner. Bir sorun yaşandığında aracı güvenli beklemeye almak için kullanılır.
2. **Return ve Land Modları:** `Return` modu belirlenen parametrelere göre kalkış yapılan ev konumuna  geri dönmeyi sağlar; `Land` ve `Takeoff` ise otonom iniş ve kalkış modlarıdır.
3. **Offboard Mode:** Uçuş kontrolcüsünün karar mekanizmasını harici bir sisteme devrettiği özel otonom moddur.
    - **MAVLink** veya **ROS 2** üzerinden gönderilen komutlarla çalışır.
    - Görev bilgisayarından doğrudan X, Y, Z konum, **hız vektörü**, **ivme vektörü**, **gövde açısı** veya doğrudan **itki** komutları verilebilir.
    - Engelden sakınma, görsel konumlama, sürü İHA yönetimi ve görüntü işleme görevlerinde kullanılır.
    - **Güvenlik Önlemleri:** Eğer görev bilgisayarından gelen komut akışı kesilirse PX4 güvenliği sağlamak için kendini otomatik olarak **Failsafe** moduna alır. Ayrıca sabit kanatlı bir İHA'da dışarıdan verilen bir komut uçağı **stall** durumuna sokacaksa, PX4 kendi güvenlik sınırlarıyla bu tehlikeli komutu engeller.

## **Video 7: Drone Programlama Kütüphaneleri**

**Drone Programlama Nedir ve Ekosistem Nasıldır?**
Drone programlama; otopilot yazılımlarına dışarıdan bir komut yollama veya otopilot yazılımının sahip olduğu İHA durum bilgilerini yer kontrol istasyonuna ya da görev bilgisayarına iletmesidir. Ekosistem üç ana bileşenden oluşur:

1. **Flight Control :** ArduPilot ve PX4.
2. **Ground Control Station :** QGroundControl, Mission Planner.
3. **Companion Computer :** Raspberry Pi, NVIDIA Jetson vb.

**İletişim Protokolleri: MAVLink ve DDS Karşılaştırması:**

1. **MAVLink Protokolü:**
    - Çok hafif , komutların ve verilerin **byte** büyüklüğünde taşındığı bir protokoldür. Paket yapısı içinde mesaj komutu, İHA'nın `System ID`si, `Payload` ve doğrulama için `Checksum` değerleri yer alır.
    - **Kullanım Alanı:** Uzak mesafelerdeki haberleşmenin %99'unda  **MAVLink** kullanılır. Çünkü mesafe arttıkça bant genişliği  kısıtlanır ve sinyal zayıflar; MAVLink hafif olduğu için uzak mesafede veri bozulmadan doğru ve hızlı şekilde ulaşır.
2. **DDS (Data Distribution Service) ve ROS 2:**
    - 2000'lerin başından beri askeri sistemlerde kullanılan DDS teknolojisi, önce PX4  ardından ArduPilot  tarafından benimsenmiş ve **ROS 2** ile birlikte standart haline gelmiştir .
    - **Kullanım Alanı ve Avantajı:** İHA üzerindeki görev bilgisayarı  ile uçuş kontrolcüsü  arasındaki **kısa mesafeli** bağlantıda kullanılır. DDS, İHA'nın tüm sensör verilerini  çok yüksek yenileme hızlarıyla  neredeyse gecikmesiz olarak görev bilgisayarına aktarır ve komutları anında otopilota iletir.
    - **Neden İhtiyaç Duyulur?** Örneğin Teknofest **Savaşan İHA** yarışmasında 25-30 m/s hızla giden İHA'lar havada birbirini kovalarken görüntü işlemeyle tespit edilen hedefe kilitlenmek için verinin çok hızlı okunması ve komutun milisaniyeler içinde otopilota iletilmesi gerekir.
    - **Dezavantajı:** Çok yüksek veri trafiği ve bant genişliği kullandığı için uzun mesafeli telemetride sinyal zayıfladığında kopar; ayrıca yoğun veri akışını işleyebilmek için düşük RAM'li eski kartlar yerine **Raspberry Pi 5** veya **Jetson Orin** gibi güçlü görev bilgisayarları gerektirir.

**Drone Programlama Kütüphaneleri:**

1. **Pymavlink:**
    - Doğrudan MAVLink protokolünün en alt seviye yapısını kullanan Python kütüphanesidir. `drone.takeoff()` gibi hazır üst seviye fonksiyonları yoktur; `System ID`, `Frame`, `Command` ve `Payload` byte'larını elimizle oluşturup `send` komutuyla göndeririz.
    - Her zaman çalışır ve çok ince kontrol sağlar.
2. **MAVSDK:**
    - Hem PX4 hem ArduPilot için kullanılabilen ancak **özellikle PX4 için geliştirilmiş**, kullanımı çok kolay ve güncel bir kütüphanedir.
    - `.arm()`, `.takeoff()` gibi modüler hazır fonksiyonlar sunar ve **C++, Python, Java, Swift** gibi birçok dilde API desteği vardır. ArduPilot ile temel fonksiyonları çalışsa da bazı özellikleri çalışmayabilir.
3. **ROS 2:**
    - Sadece otopilot haberleşmesi değil; İHA üzerine takılan **360 derece Lidar, Radar, Sonar, Derinlik Kamerası** gibi harici robotik sensörleri, görev bilgisayarını ve Pixhawk'u **tek bir bütün sistem** halinde birleştiren ekosistemdir.
    - **Topic** mantığıyla çalışır. Öğrenmesi daha zordur ancak yüksek hız ve sensör entegrasyonu gerektiren görev bilgisayarlarında en güçlü çözümdür.
4. **DroneKit:**
    - Eskiden ArduPilot için çok kullanılan ve kullanımı kolay bir kütüphaneydi; ancak uzun yıllar önce geliştirilmesi durdurulduğu için artık tercih edilmemektedir.

**Hangi Durumda Hangi Kütüphane Seçilmeli?**

- **Uzaktan veya Basit Görev Bilgisayarı Haberleşmesi:**
    - **PX4 kullanıyorsak:** Hem kullanım kolaylığı hem güncellik açısından **MAVSDK** en iyi tercihtir.
    - **ArduPilot kullanıyorsak:** Test edilerek **MAVSDK** kullanılabilir veya tam uyumluluk için **Pymavlink** tercih edilmelidir.
- **Yüksek Hız, Görüntü İşleme ve Robotik Sensör Entegrasyonu Gerektiren Görevler :**
    - Hem **PX4** hem de **ArduPilot** için ortak olarak görev bilgisayarında **ROS 2** kullanılmalıdır.

## **Video 8: İHA Simülasyon Ortamları**

**Simülasyon Ortamlarının Amacı:**
Simülasyon ortamları, gerçek hayatta insansız hava aracımızı uçurmadan önce kodlarımızı ve algoritmalarımızı test etmemizi, görevimizin nasıl işleyeceğini güvenli bir şekilde görmemizi sağlar. En bilinen 5 simülasyon ortamı şunlardır:

1. **Gazebo:**
    - En çok kullandığımız, 10 yıldan uzun süredir hem **ArduPilot**'a hem **PX4**'e hem de genel robotik projelerine hizmet veren açık kaynaklı simülasyon ortamıdır.
    - Sadece PX4'ün kendi Gazebo GitHub reposunda bile 10-15 farklı hazır İHA modeli vardır: `x500` ve kameralı versiyonları, `standard_vtol`, `rc_cessna`, `advanced_plane`, `quad_tailsitter`, `tiltrotor` ve `rover` gibi araçlar doğrudan simüle edilebilir.
2. **Microsoft AirSim:**
    - **Unreal Engine 4** oyun motoru üzerine kurulmuş bir simülatördür. Şu an güncelleme almamaktadır ve topluluğu küçüktür; yeni bir sabit kanat veya farklı bir döner kanat eklemek zordur.
    - **Avantajı:** Unreal Engine 4 sayesinde ev modelleri, güneş/gölge efektleri, mağaza ve tabelalar gibi gerçekçi bir dünya sunar. Özellikle drone teslimatı gibi gerçek dünya görsellerini simülasyon kamerasından alıp görüntü işleme algoritmalarını test etmek isteyen akademik çalışmalar için yararlıdır.
3. **MATLAB & Simulink:**
    - Akademik olarak ve kontrol mühendisliğinde çok fazla kullanılan bir uygulama ve simülatördür.
    - **Amacı:** Alt seviye kontrol algoritmalarını, sensör füzyonunu, sensör işleme modellerini ve uçuş kontrol tasarımlarını matematiksel olarak modelleyip test etmek için kullanılır.
4. **jMAVSim:**
    - Çok güncel olmayan ve görsel olarak eski kalan basit bir simülatördür.
    - Kamera bağlamak veya karmaşık ortam görevleri yapmak gerekmeyen durumlarda, sadece PX4 üzerinde temel `arm`, `takeoff` ve `waypoint` kodlarını hızlıca test etmek için kullanılabilir.
5. **NVIDIA Isaac Sim:**
    - NVIDIA'nın **RTX** serisi ekran kartlarıyla çalışan ve özellikle **Reinforcement Learning** modelleriyle geliştirilen robotik projelerinde kullanılan modern simülatördür.
    - **Pegasus** eklentisiyle PX4 ve ROS 2 buraya bağlanarak RTX ekran kartlarının gücüyle pekiştirmeli öğrenme algoritmaları ve İHA simülasyonları birlikte çalıştırılabilmektedir.
